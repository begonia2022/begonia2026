# Work Skill 提取维度

## 任务

从已收集的原材料（聊天记录、文档、邮件、粘贴文本）和用户手动信息中，
提取这个人的**工作能力画像**，供 `work_builder.md` 生成 `work.md`。

## 提取维度

### 1. 负责系统 / 领域

- 他负责哪些系统、模块、业务线？
- 他对这些系统的核心判断和结论是什么？
- 他自认为的"专业领域"和"一亩三分地"是哪里？

### 2. 技术规范与代码风格

- 代码/文档规范偏好：命名、目录结构、注释习惯、测试要求
- 接口设计原则：他反复强调的"标准做法"是什么？
- 有哪些口头上的"红线"（绝不允许的写法/做法）？

### 3. 工作流程

- 他做事的顺序：先做什么、后做什么？
- 对流程/规范的遵守程度：照章办事还是灵活变通？
- 交付节奏：何时汇报、如何同步进度、如何验收？

### 4. 输出偏好

- 交付物形态：文档、PPT、代码、口头结论？
- 格式偏好：结论先行还是铺垫？列点还是长文？
- 对"完整度"的要求：做到 60% 还是追求 100%？

### 5. 经验知识

- 踩过的坑、沉淀的结论（"以前遇到过……所以现在……"）
- 他对某些技术/方案的明确好恶与理由
- 可复用的判断规则（"遇到 X 就做 Y"）

## 按职位类型调整侧重

- **后端**：接口设计、数据库、性能、稳定性、并发、容量评估
- **前端**：组件设计、交互细节、性能优化、兼容性
- **算法**：数据口径、评测标准、模型选型、上线流程
- **产品**：需求优先级、竞品分析、数据指标、PRD 质量
- **设计**：设计规范、审美原则、交付标注、评审流程

## 输出

输出结构化的提取结果，标注每条结论的**来源**（哪份材料/哪句话），
供 `work_builder.md` 直接使用。信息不足的维度标注「（信息不足）」。
